MINDSET SHIFT Flutter → Swift
Flutter Way

Widget Tree is King

Everything is a Widget, mutability is explicit via StatefulWidget. You call setState() and Flutter rebuilds the subtree. State lives inside widget classes.

SwiftUI Way

Value Types + Reactivity

Views are structs (value types!), not classes. The framework observes property changes automatically. Mutations to @State properties auto-trigger redraws. No explicit "rebuild" call needed.

Flutter Way

Methods as modifiers

Container(color: Colors.blue, child: Text('hello')). Properties passed as constructor params. Wrapping widgets creates hierarchy.

SwiftUI Way

Modifier chaining

Text("hello").foregroundColor(.blue).font(.title). Each modifier returns a new view wrapping the previous. Order matters — modifiers apply from bottom to top structurally.

Flutter Way

Dart is OOP-first

Everything is an object. Classes extend other classes. Null safety is explicit with ? and !. No value semantics by default.

SwiftUI Way

Swift is Protocol-first

Protocols over inheritance. Structs are first-class citizens. Optionals are built into the type system. Value semantics by default — structs copy, classes reference.

LANGUAGE BASICS Dart vs Swift

Variables & Constants

DART
// Variables
var name = 'Alice';       // inferred String
String name2 = 'Bob';   // explicit type
final age = 30;           // runtime constant
const PI = 3.14;         // compile-time const

// Null safety
String? nullableName;    // can be null
String nonNull = 'hi';  // never null
var len = nullableName?.length ?? 0;
SWIFT
// Variables
var name = "Alice"        // inferred String
var name2: String = "Bob"  // explicit
let age = 30              // constant (like final)
let PI = 3.14             // also let

// Optionals (Swift's null safety)
var nullableName: String?  // Optional String
var nonNull: String = "hi" // always has value
let len = nullableName?.count ?? 0
💡
Key difference: Swift uses let for ALL constants (both runtime and compile-time). Dart splits into final (runtime) and const (compile-time). Swift's var = Dart's var/late.

Functions

DART
// Basic function
String greet(String name) {
  return 'Hello, $name!';
}

// Named params (optional by default!)
void showDialog({
  required String title,
  String? message,
}) { }

// Arrow function
int double(int x) => x * 2;

// Closure / lambda
var add = (int a, int b) => a + b;
SWIFT
// Basic function
func greet(name: String) -> String {
  return "Hello, \(name)!"
}

// Argument labels (external + internal)
func showDialog(title: String,
                 message: String? = nil) { }

// Shorthand (single expression)
func double(x: Int) -> Int { x * 2 }

// Closure
let add: (Int, Int) -> Int = { a, b in a + b }
let add2 = { $0 + $1 } // shorthand args
🔑
Argument labels: Swift functions have TWO names per param — an external label (what caller sees) and internal name. Example: func move(from start: Int, to end: Int) — you call it as move(from: 0, to: 100). Use _ to hide the label: func greet(_ name: String) → greet("Alice").

Types: Classes, Structs & Protocols

DART
// Dart: class-first
class User {
  String name;
  int age;

  User({required this.name, required this.age});

  String get display => '$name ($age)';
}

// Abstract class (interface-like)
abstract class Animal {
  String sound(); // must implement
}

// Mixins
mixin Flyable {
  void fly() => print('flying');
}
SWIFT
// Swift: struct-first (value type)
struct User {
  var name: String
  var age: Int

  // computed property
  var display: String { "\(name) (\(age))" }
}
// Memberwise init auto-generated!
let user = User(name: "Alice", age: 30)

// Protocol (like abstract class/interface)
protocol Animal {
  func sound() -> String // must implement
  var name: String { get }
}

// Extension (adds methods to ANY type)
extension String {
  var uppercasedFirst: String {
    prefix(1).uppercased() + dropFirst()
  }
}
⚠️
Struct vs Class: Swift structs are copied when passed around (value semantics). Classes are referenced. SwiftUI Views are structs — this is intentional! Use class for reference semantics, struct for data. Most of your data models should be structs.

Optionals (Swift's Null Safety)

DART
String? name; // nullable

// Null-aware ops
var len = name?.length;  // int?
var len2 = name?.length ?? 0;

// Force unwrap (dangerous!)
var len3 = name!.length;

// Null check
if (name != null) {
  print(name.length); // auto promoted
}
SWIFT
var name: String? // Optional String

// Optional chaining
let len = name?.count  // Int?
let len2 = name?.count ?? 0

// Force unwrap (use cautiously)
let len3 = name!.count

// if let (safe unwrap)
if let name {
  print(name.count) // name is String here
}

// guard let (early exit pattern)
guard let name else { return }
// name is String from here on

Collections

DART
// List
var nums = [1, 2, 3];
var mapped = nums.map((n) => n * 2).toList();
var filtered = nums.where((n) => n > 1).toList();

// Map (Dictionary)
var dict = {'key': 'value', 'age': 30};
var age = dict['age']; // dynamic type

// Set
var set = {1, 2, 3};

// Spread operator
var combined = [...nums, 4, 5];
SWIFT
// Array
var nums = [1, 2, 3]
let mapped = nums.map { $0 * 2 }
let filtered = nums.filter { $0 > 1 }

// Dictionary
var dict: [String: Any] = ["key": "value"]
let age = dict["age"] // returns Any?

// Set
var set: Set = [1, 2, 3]

// Combine arrays
let combined = nums + [4, 5]
nums.append(contentsOf: [4, 5])

Error Handling

DART
// Dart: try-catch
try {
  var result = await fetchData();
} catch (e) {
  print('Error: $e');
} finally {
  // always runs
}

// Custom exception
class AppError implements Exception {
  final String message;
  AppError(this.message);
}
SWIFT
// Swift: throws/try
do {
  let result = try await fetchData()
} catch {
  print("Error: \(error)")
} // (no finally, use defer)

// Custom error (enum-based!)
enum AppError: Error {
  case networkFailed
  case invalidData(String)
}

// Function that can throw
func fetchData() throws -> Data { ... }

// try? returns Optional, try! force-unwraps
let data = try? fetchData() // Data?

Enums — Swift's Superpower

DART

  loading,

  error

SWIFT

  case loading
  case success(Data)          // payload!

  case blue = "#0000FF"

PROPERTY WRAPPERS State Toolbox
@State
Local view state owned by this view. SwiftUI watches it and redraws when it changes. Private — don't share with other views.
≈ Flutter: setState() variable
@State private var count = 0
Button("+") { count += 1 }
Text("Count: \(count)")
@Binding
A two-way reference to state owned by a parent view. Changes here propagate back up. Used for child views that need to mutate parent state.
≈ Flutter: passing callbacks + value
// Parent
@State private var name = ""
NameField(name: $name)  // $ = binding

// Child
struct NameField: View {
  @Binding var name: String
}
@Observable iOS 17+
Modern replacement for ObservableObject. Annotate your model class and SwiftUI auto-tracks which properties your views actually read. No @Published needed!
≈ Flutter: ChangeNotifier / Riverpod
@Observable
class CartModel {
  var items: [Item] = []
  func add(_ item: Item) { items.append(item) }
}

// In view:
var cart: CartModel  // just use it!
@Environment
Read values injected into the environment by parent views or the system. System provides colorScheme, locale, dismiss, openURL, and more. Pass your models this way app-wide.
≈ Flutter: InheritedWidget / Provider
// Read system value
@Environment(\.colorScheme) var scheme

// Inject your model
@Environment(CartModel.self) var cart
@AppStorage
Reads/writes directly to UserDefaults and syncs with SwiftUI. Perfect for user preferences, settings, and small persistent data that should survive app restarts.
≈ Flutter: SharedPreferences
@AppStorage("username")
var username = ""

// Auto-saves when changed!
TextField("Name", text: $username)
@StateObject / @ObservedObject
Legacy (pre-iOS 17). @StateObject owns the object's lifetime (use in parent). @ObservedObject references it (use in child). Prefer @Observable + @State for new code.
Legacy — use @Observable instead
// Old way (still works)
class VM: ObservableObject {
  @Published var count = 0
}
@StateObject private var vm = VM()
@FocusState
Controls keyboard focus for text fields. Bind to a boolean or custom enum to programmatically focus/unfocus fields and control the keyboard.
≈ Flutter: FocusNode
@FocusState private var isFocused: Bool

TextField("Email", text: $email)
  .focused($isFocused)

Button("Focus") { isFocused = true }
@SceneStorage
Like @AppStorage but tied to a specific scene/window. Automatically saves and restores when the app goes to background. Great for UI state like selected tab.
≈ Flutter: PageStorage
@SceneStorage("selectedTab")
var selectedTab = 0

// Survives backgrounding, not reinstall

CONCURRENCY Swift 6.2
⚡
Swift 6.2 introduces "Approachable Concurrency" — making async/await dramatically simpler. New projects default to running on the main actor, async functions no longer randomly hop to background threads, and the new @concurrent attribute makes parallelism explicit.

async / await

DART

Future<User> fetchUser(int id) async {
  final response = await http.get(url);
  return User.fromJson(response.body);
}

// Using it

  try {
    final user = await fetchUser(1);

  } catch (e) {
    setState(() => _error = e.toString());
  }

  fetchUser(1),

// Swift async
func fetchUser(id: Int) async throws -> User {
  let (data, _) = try await URLSession.shared
    .data(from: url)

Actors — Thread Safety Made Easy

DART
// Dart: Isolates for thread safety
import 'dart:isolate';

void heavyWork(SendPort port) {
  // runs in separate isolate
  final result = compute(1000000);
  port.send(result);
}

// compute() helper for simple cases
final result = await compute(
  (data) => processData(data),

SWIFT 6.2
// Actor — thread-safe by default
actor DataStore {
  private var cache: [String: Data] = [:]

  func store(data: Data, key: String) {
    cache[key] = data  // safe, serialized
  }

  func get(key: String) -> Data? {
    cache[key]
  }

  // @concurrent = safe parallel execution (Swift 6.2)
  @concurrent
  func heavyComputation() async -> Int {
    // Runs off actor queue — safe for parallel calls
    return calculateSomething()
  }
}

// Must await actor access
let store = DataStore()
await store.store(data: data, key: "user")

@MainActor — UI Thread

Swift 6.2
// @MainActor = must run on main thread
// SwiftUI views are @MainActor automatically

@MainActor
class ViewModel {
  var items: [Item] = []

  func loadItems() async {
    // Jump to background for network
    let data = await Task.detached {
      try await fetchFromAPI()
    }.value

    // Back on @MainActor automatically
    items = data  // ✅ safe UI update
  }
}

// Swift 6.2: New projects are @MainActor by default!
// No more surprise thread hops in async functions

// nonisolated async now stays on caller's actor
func loadUserData() async -> User {
  // In Swift 6.2: runs on whatever actor called this
  // No more surprise hops to global executor!
  return await apiClient.fetchUser()
}

Task & Structured Concurrency

Task

Create concurrent work from synchronous context. Tasks inherit actor context.

// Fire async work from sync
Button("Load") {
  Task {
    await viewModel.load()
  }
}

// With priority
Task(priority: .background) {
  await cleanupCache()
}

// Detached (no actor inheritance)
Task.detached {
  await heavyWork()
}

TaskGroup

Run multiple concurrent tasks and collect their results. Like Promise.all().

let images = try await
  withThrowingTaskGroup(of: UIImage.self) { group in

  for url in imageURLs {
    group.addTask {
      try await downloadImage(url)
    }
  }

  var results: [UIImage] = []
  for try await image in group {
    results.append(image)
  }
  return results
}

AsyncSequence

Iterate over async values as they arrive. Like Dart's Stream.

// Like Dart's Stream / StreamBuilder
for await update in locationUpdates {
  currentLocation = update
}

// Create your own
let stream = AsyncStream(Int.self) { cont in
  for i in 0..<10 {
    cont.yield(i)
  }
  cont.finish()
}

for await num in stream {
  print(num)
}

async let (Parallelism)

Start multiple async tasks simultaneously and await all results together.

// Sequential (slow)
let user = try await fetchUser()
let posts = try await fetchPosts()

// Parallel (fast!)
async let user = fetchUser()
async let posts = fetchPosts()
let (u, p) = try await (user, posts)
// Both network calls happen simultaneously!

SwiftData (iOS 17+) is Apple's modern replacement for CoreData. It's Swift-native, works with @Observable, and integrates directly into SwiftUI. In Xcode 26, SwiftData gained model inheritance. Think of it like Flutter + Hive/Isar but built by Apple.
SwiftData
// 1. Define your model
import SwiftData

@Model
class Note {
  var title: String
  var content: String
  var createdAt: Date

  init(title: String, content: String) {
    self.title = title
    self.content = content
    self.createdAt = .now
  }
}

// 2. Set up the container in @main
WindowGroup { ContentView() }
  .modelContainer(for: Note.self)

// 3. Query in views
struct NotesView: View {
  @Query(sort: \.createdAt, order: .reverse)
  var notes: [Note]

  @Environment(\.modelContext) var context

  var body: some View {
    List(notes) { note in Text(note.title) }
      .toolbar {
        Button("Add") {
          let note = Note(title: "New", content: "")
          context.insert(note)  // auto-saved!
        }
      }
  }
}

// 4. Delete
context.delete(note)  // that's it!

// 5. Filtered queries
@Query(filter: #Predicate<Note> {
  $0.title.contains("Swift")
})
var swiftNotes: [Note]
